filesquid-metadata component diagram

Metadata module of FileSquid · apps/filesquid/crates/metadata · drawn against the code on filesquid-product · 2026-10-15

filesquid-metadata is the metadata module of FileSquid for namespaced file metadata, and it is still installable on its own: it extracts embedded technical metadata and creates and edits Dublin Core and Schema.org description (ADRs 024, 029). FileSquid UIs reach it only through the one FileSquid API (filesquid-api, ADR 030), served by the filesquid-desktop and filesquid-server hosts. Its core works today: the /terms/ register, CSV, the JSON sidecar, the metadata.md codec and the CLI. Extraction is path-based, XMP is partial, and the pluggable stores, WASM build, API routes and the <fs-metadata-panel> custom element in @filesquid/ui are planned.

Code and design drift

Two places where the code still reflects the pre-ADR 027 design: the crate description and lib.rs doc comment say it persists through filesquid-ocfl, and Cargo.toml and the isolation test make filesquid-ocfl a required dependency. ADR 027 makes it the optional ocfl store (Task 0.15).

Boundaries

OwnsDoes not own
Descriptive and technical facts: embedded EXIF, ID3, IPTC, XMP, format identification, capture dates, Dublin Core and Schema.org description, titles, captions, keywords, rightsStorage facts (filesquid-ocfl), Content Credentials (filesquid-c2pa), application meaning such as albums and favorites (distribution UI layers such as ImageSquid). Never links Axum, Tauri, libvips, FFmpeg, SQLite by default, filesquid-core or filesquid-api; no MODS or SQL interchange.
