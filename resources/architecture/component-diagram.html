FileSquid component diagram

ADRs 001–032 drawn against the code on branch filesquid-product · 2026-10-15

FileSquid is one Rust backend with one API. UI distributions (the FileSquid default UI, ImageSquid, later Arkrim) are static vanilla TypeScript that call that API and contain no backend code. Hosts mount the same API router: the desktop app in-process, filesquid-server over HTTP, and later an encrypted browser host as WebAssembly. The paid service at *.filesquid.tech stores and relays ciphertext only and never links the modules. Every box is styled by how much of it exists in code today, and every arrow by whether that interaction works yet. Module pages: ocfl, metadata and c2pa.

Who owns which file fact

OwnerFacts
filesquid-ocflStorage facts: object ID, logical path and implied folders, versions, version created/user/message, digests and fixity, size, content location. The extension-based type label is a display hint only.
filesquid-metadataDescriptive and technical facts: embedded EXIF/ID3/IPTC/XMP, format identification, capture dates, Dublin Core and Schema.org description, titles, captions, keywords, rights.
filesquid-c2paContent Credentials: manifests, validation results, signers, ingredients, actions.
FileSquid application layer (filesquid-api and later modules)Application meaning: collections, people, favorites, search indexes, recipes. Distributions present it; they do not compute it.
